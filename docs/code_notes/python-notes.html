Development Process

  1. Mathematics - decide on the application itself and the mathematical method it will apply
  2. Setup repo - see package design
  3. Setup version control
  4. Decide if you are creating a script or library module
  5. git branch for new feature, such as a new script or library module
  6. Use pip install -e . to develop, run tests over the project
  7. When a script/class is complete, profile with timeit or cProfile to optimize (optional)
  8. Format with black and pylint.
  9. At each complete unit of work (when a new feature has been implemented), commit the changes to the branch. Commit also when you have made changes you may want to undo.
  10. git push at the end of the day or when the branch is merged
  11. package and publish (if necessary)

Scripts vs. libraries vs. notebooks

When developing python scripts vs library modules, the former is for performing a particular task with well defined inputs and outputs, the latter is for creating useful classes and functions that are imported by other code. They are designed to abstract tasks and be reused frequently. The development process is very different.

Developing a library module:

  1. create the library module
  2. Design classes - what they will do, what are the nouns (objects) and verbs (functions) of the software, class compositions
  3. Write documentation as you go - see documentation section
  4. Write tests - in separate tests folder, use pytest for running them - follow the test-driven-development process
  5. Write classes - test as you go

Develop a script:

  1. Copy the script template
  2. decide on the task of the script, define the desired input and output
  3. Analysis scripts are best when modular, this means that if it is getting too large, split the analysis into separate scripts doing a particular task with well defined inputs and outputs.
  4. The key is iteration rate, make sure there is a ‘fast’ mode, or a small input size for development and debugging before the ‘big’ run.
  5. Debug with pdb or IDE debugger as you go

A python project can be a single script, a pure library, a library with a single “run” or “main” script or a set of scripts together with a library of common code utilities. Avoid using debugging for library modules, instead prefer a good set of unit tests. Scripts are the reverse, rely on a debugger. You shouldn’t need a lot of unit tests for the components of a script, if you do, this is a sign that function or class might be better added to a library of utilities and covered by unit tests.

Developing a notebook

The purpose of a notebook is interactive, procedural analysis. Usually this will be in jupyter notebooks but I prefer using pycharm’s code cells and standard python scripts.

  • These do not have the standard main function
  • No arguments, and not run on the command line
  • do retain the rest of the structure of a script

Testing & debugging

  • test-driven development

requirements are turned into very specific test cases, then the code is improved so that the tests pass. A unit test checks the output of a small component of the whole application. One can write unit and integration tests with the help of the pytest and unittest libraries.

It helps to install a editable version using pip install -e . this will allow you to change the code, while running tests.

Unit tests

  • pytest unit tests

The key keyword is the assert term. This term will take in a boolean argument but only raise an error if the argument is false. It is used in unit test functions like so

def test_sum():
    assert sum([1, 2, 3]) == 6, "Should be 6"

  • There will usually be a test function like test_sum for each function or class (in the case of classes, the class is instantiated and all methods are tested within one test_class function).

  • One can combine pytest and debugging with the --pdb flag, which opens pdb on errors found by pytest

  • One can benchmark a test with pytest-benchmark to log the timing of each test case. This tells us the time of execution as well as evaluation

def test_my_function(benchmark):
    result = benchmark(test)
  • Fixtures are a way of providing data, test doubles, or state setup to your tests. Fixtures are great for extracting data or objects that you use across multiple tests.
@pytest.fixture
def example_people_data():
    return [
        {
            "given_name": "Alfonsa",
            "family_name": "Ruiz",
            "title": "Senior Software Engineer",
        },
        {
            "given_name": "Sayid",
            "family_name": "Khan",
            "title": "Project Manager",
        },
    ]

def test_format_data_for_display(example_people_data):
    assert format_data_for_display(example_people_data) == [
        "Alfonsa Ruiz: Senior Software Engineer",
        "Sayid Khan: Project Manager",
    ]

def test_format_data_for_excel(example_people_data):
    assert format_data_for_excel(example_people_data) == """given,family,title
Alfonsa,Ruiz,Senior Software Engineer
Sayid,Khan,Project Manager
"""

  • You can run specific tests with :: pytest test_file.py::test_func_name

  • Parametrization is used to combine the multiple test cases into one test case.

@pytest.mark.parametrize(“num”, “result”, [(1, 11), (2,22), (3,33), (4,44), (5,55)]
def test_calculation(num, result):
  assert 11*num == result
  • Use the --durations option to the pytest command to include a duration report in your test results. --durations expects an integer value n and will report the slowest n number of tests. pytest --durations=3
  • You can group tests into a larger test class
# content of test_class.py
class TestClass:
    def test_one(self):
        x = "this"
        assert "h" in x

    def test_two(self):
        x = "hello"
        assert hasattr(x, "check")
  • unittest testing

Using unittset requires putting each test into a class and using assertEqual, assertFalse, assertTrue methods

import unittest


class TestSum(unittest.TestCase):

    def test_sum(self):
        self.assertEqual(sum([1, 2, 3]), 6, "Should be 6")

    def test_sum_tuple(self):
        self.assertEqual(sum((1, 2, 2)), 6, "Should be 6")

if __name__ == '__main__':
    unittest.main()
  • Coverage

Code coverage is the proportion of your code covered by tests. A useful tool is coverage

coverage run -m pytest arg1 arg2

Coverage can also be performed with pytest-cov which unifies pytest and coverage.

Debugging

Use the pdb module to debug python programs. use it on scripts by calling

python -m pdb script.py

then step through the lines of code with n and s or use p to print output

list source code with ll

use b to set breakpoints and use c to continue until breakpoint

debugging in IDEs

It is easy now to debug with an IDE like Pycharm. The debugging loop consists of:

  1. open the debugger
  2. create breakpoints
  3. start the debugger by using “Run and debug”, selecting the script you want to debug
  4. step through the lines of code to view variable values

The debugger is a fully functioning interpreter, so you can inspect variables, and reset others.

Documentation

Docstrings

A docstring is a string that is the first statement in a package, module, class or function. These strings can be extracted automatically through the doc member of the object. A docstring should give enough information to write a call to the function without reading the function’s code.

Standard google style for function docstrings:

def fetch_bigtable_rows(big_table, keys, other_silly_variable=None):
    """Fetches rows from a Bigtable.

    Retrieves rows pertaining to the given keys from the Table instance
    represented by big_table.  Silly things may happen if
    other_silly_variable is not None.

    Args:
        big_table: An open Bigtable Table instance.
        keys: A sequence of strings representing the key of each table row
            to fetch.
        other_silly_variable: Another optional variable, that has a much
            longer name than the other args, and which does nothing.

    Returns:
        A dict mapping keys to the corresponding table row data
        fetched. Each row is represented as a tuple of strings. For
        example:

        {'Serak': ('Rigel VII', 'Preparer'),
         'Zim': ('Irk', 'Invader'),
         'Lrrr': ('Omicron Persei 8', 'Emperor')}

        If a key from the keys argument is missing from the dictionary,
        then that row was not found in the table.

    Raises:
        IOError: An error occurred accessing the bigtable.Table object.
    """

Standard google style for module docstring:

"""A one line summary of the module or program, terminated by a period.

Leave one blank line.  The rest of this docstring should contain an
overall description of the module or program.  Optionally, it may also
contain a brief description of exported classes and functions and/or usage
examples.

  Typical usage example:

  foo = ClassFoo()
  bar = foo.FunctionBar()
"""

after the module docstring you should structure your imports:

# Standard library imports
import datetime
import os

# Third party imports
from flask import Flask
from flask_restful import Api
from flask_sqlalchemy import SQLAlchemy

# Local application imports
from local_module import local_class
from local_package import local_function

Numpy-style docstrings

class Animal:
    """
    A class used to represent an Animal

    ...

    Attributes
    ----------
    says_str : str
        a formatted string to print out what the animal says
    name : str
        the name of the animal
    sound : str
        the sound that the animal makes
    num_legs : int
        the number of legs the animal has (default 4)

    Methods
    -------
    says(sound=None)
        Prints the animals name and what sound it makes
    """

    says_str = "A {name} says {sound}"

    def __init__(self, name, sound, num_legs=4):
        """
        Parameters
        ----------
        name : str
            The name of the animal
        sound : str
            The sound the animal makes
        num_legs : int, optional
            The number of legs the animal (default is 4)
        """

        self.name = name
        self.sound = sound
        self.num_legs = num_legs

    def says(self, sound=None):
        """Prints what the animals name is and what sound it makes.

        If the argument `sound` isn't passed in, the default Animal
        sound is used.

        Parameters
        ----------
        sound : str, optional
            The sound the animal makes (default is None)

        Raises
        ------
        NotImplementedError
            If no sound is set for the animal or passed in as a
            parameter.
        """

        if self.sound is None and sound is None:
            raise NotImplementedError("Silent Animals are not supported!")

        out_sound = self.sound if sound is None else sound
        print(self.says_str.format(name=self.name, sound=out_sound))
  • no need to add a description for python special methods, only define the parameters and returns
  • Don’t bother listing the methods in the class top docstring, just the attributes
  • Don’t document private methods and attributes

Type hints

Type hints are not necessary for a dynamically typed language like python, but they do improve readability and allow static analysis to ensure you use inputs and outputs correctly. Use type checking via the mypy tool.

mypy script.py

It will look over you code and check for errors in types. For it to work you must put Rust-like type annotations into the function/class signatures

def greeting(name: str) -> str:
    return 'Hello ' + name

basic types are supported str,int,float,bool,complex, None. For compound types, import them from the typing module. from typing import <>. List,Dict,Tuple,Iterable, Union, Set, Generator. These must be defined with the data type they hold. eg. List[str], Dict[int, float], Tuple[bool]

derived types: one can create type aliases for a specific type to aid comprehension

from typing import List, Dict, Tuple

ConnectionOptions = Dict[str, str]
Address = Tuple[str, int]
Server = Tuple[Address, ConnectionOptions]
Vector = List[float]

def stringify(x: float) -> str:
    return str(x)

def summing(x: List[int]) -> int:
    ans = 0
    for i in x:
        ans += i
    return ans

def main():
    a_list = [2, 3, 4]
    summed = summing(a_list)
    stringed = stringify(4.6)
    string_list = stringify(a_list)
    print(a_list)
    print(summed)
    print(stringed)
    print(string_list)

if __name__ == "__main__":
    main()

Pydantic

Pydantic is a data validation module that allows you to do type checking at test/runtime. It works alongside the typing library and can be a good way of avoiding all the assert/isinstance blocks.

from datetime import datetime
from typing import Tuple

from pydantic import BaseModel


class Delivery(BaseModel):
    timestamp: datetime
    dimensions: Tuple[int, int]


m = Delivery(timestamp='2020-01-02T03:04:05Z', dimensions=['10', '20'])
print(repr(m.timestamp))
#> datetime.datetime(2020, 1, 2, 3, 4, 5, tzinfo=TzInfo(UTC))
print(m.dimensions)
#> (10, 20)

Formatting & linting

Format and lint python code to be clean, well written and conforming to a style. The best two tools are black and pylint. Also useful is isort which auto-sorts your imports. Also try ruff for faster linting

PEP8 is the python style guide. For readable, maintainable code, it is best to conform to the style guide. One can use a linter such as pylint to check for logical and stylistic errors.

format python code with black

best way to ensure style is to just run the black formatter over the whole package like black neuroNLP/

Pickling is the serialization of a python object, that is it changes a python object hierarchy into a byte stream. Done with the pickle library (cPickle is faster, being in C). Useful for storing objects for future use and archiving.

Profiling & logging

Python can be profiles with timeit

python -m timeit script.py

Python code can be profiled with cProfile. This can be used on a script like so:

python -m cProfile script.py

output a profile data file with

python -m cProfile -o script.profile script.py

then one can use pstats to analyse the profile

python -m pstats script.profile

Alternatively one can use it inside a main function like so

if __name__ == "__main__":
    # main()
    import cProfile

    cProfile.run("main()", "pipe.profile")

Python logging

  • useful for debugging purposes, particularly when a debugger cannot be used to step through a program.
  • the logging standard package provides debug, info, warning, error, critical functions to output logging info.
  • Normally the output is sent to stdout to the terminal, but we can also save it to a file by specifying the logging config. logging.basicConfig(level=logging.DEBUG, filename="output.log")
  • You can customize the output format using the format keyword to config
  • Set the log level, and the logger will only record info over and above that level, (DEBUG-INFO-WARNING-ERROR)
import logging
logging.basicConfig(level=logging.WARNING)
logging.info("starting program")
logging.debug(f"start value is {x}")
logging.warning("warning: this is a warning")
logging.error("warning: this is a warning")

Environments, modules & packaging

Each environment can use different versions of package dependencies and Python. Each project should have its own environment. They allow you to isolate each project and its dependencies.

Package - A folder/directory that contains init.py file. Module - A valid python file with .py extension.

The best tools are conda, and uv. These tools also act as package managers and module builders.

Conda

One can use different anaconda environments for different version of software to create an environment

conda create -n myenv software1 software2==2.2
conda activate myenv

To export the installed software for this environment

conda env export > environment.yml

To create an identical environment

conda env create -f environment.yml

UV

Package structure: the standard python package structure is of the form

sampleproject
├── LICENSE.txt
├── README.md
├── pyproject.toml
├── src
│   └── sample
│       ├── __init__.py
│       ├── package_data.dat
│       └── simple.py
├── tests
│   ├── __init__.py
│   └── test_simple.py
└── tox.ini

With dependencies specified in pyproject.toml

To build a package out of several python files, make sure there is a __init__.py file in each subdirectory. This file marks each directory as a python directory and allows one to do import name.module

Other optional files are data for storing datasets, models for pre-trained models, and dev for jupyter notebooks or development scripts. If there is C-code that is compiled into a cython .so library, put the C/C++ source code and .pyx files in a src directory and compiled .so files in a lib directory.

Language Features

Variables

  • The basic variable data types of python are str, int, float, complex, bool, bytes. In reality everything in python is an instance of a class. So an integer x is an instance of the int class, e.g. x = int().

  • Strings vs bytes: use encode and decode methods on strings and bytes to go from strings to bytes (utf-8 decoding most common). ASCII

  • chr, hex, bin, ord

  • isinstance, type

Collections

Basic collections

  • Both list [] and tuple () array-like index-accessed data types, however lists are mutable (you can change the elements are initialisation) but tuples are immutable (cannot change).
  • A set {}is a collection that holds an unordered collection of unique objects. set([1,2,3]) or {1,2,3} can also define set operations such as union s1.union(s2) or s1 | s2intersection s1.intersection(s2) or s1 & s2complement/difference s1.difference(s2) or s1 - s2
  • A dict {a:b} is a key-value pair mapping.

Advanced collections

  • namedtuple from collections is a tuple with named positions. You have to create this with a factory, where we specify the name of the tuple and field names. They are essentially python dataclasses, similar to how structs are used in C. They are immutable by default.
special_tuple = collections.namedtuple("special_tuple", "A B")
p1 = special_tuple(3,5)
p1.A
p1.B
  • defaultdict from collections is for when you want to have default values for dict keys. It needs to given a default function to set the default values like defaultdict(int) for 0 integer default values (could also use lambdas here). Designed to replace situations like
counter = {}
for i in "ABBDBBDA":
    if i in counter.keys():
        counter[i]+=1
    else:
        counter[i] =1

  • Counter from collections is a dict subclass for counting hashable objects. e.g. counting the number of unique strings in a list Counter(list_a). The update method is useful here when counting several lists Counter(list_a).update(list_b) and combining the result. Also useful is most_common. We can also add and subtract counters to combine the results of two counts. This class also supports and/not/or for checking union/complement/intersection.

  • OrderedDict from collections remembers order in which data was added. This means you can popitem from the top as you would a stack or iterate over the items in order as you would a list. Note for two ordereddicts to be the same the order of the data has to match as well as the items themselves.

  • deque from collections is a double-ended queue, a combination of a stack and a queue. you can pop from either side in a very memory efficient way. use the methods pop, popleft, append, appendleft, rotate to add and modify data.

  • dataclass from dataclasses reduce the boilerplate code for custom data structures with named attributes. They can create init, repr, hash and eq magic functions by default.

@dataclasses.dataclass
class Color:
    r : int = 0
    g : int = 0
    b : int = 0
Attributes init Color().r -> 0 init
Representation repr Color() -> Color(r=0, g=0, b=0) repr
Comparision* eq Color() == Color(0, 0, 0) -> True eq
Order order sorted([Color(0, 50, 0), Color()]) -> … lt, le, gt, ge
Hashable unsafe_hash/frozen {Color(), {Color()}} -> {Color(r=0, g=0, b=0)} hash
Immutable frozen + eq Color().r = 10 -> TypeError setattr, delattr

Functions & comprehensions

def func(args):
    return result
  • map, reduce, filter, any, all

NOTE: prefer list comprehensions and generator expressions over map

map applies a function to all the items in an input_list. Here is the blueprint:

map(function_to_apply, list_of_inputs)

It is an iterable, so one must use the list function to get all the elements in an array.

As the name suggests, filter creates a list of elements for which a function returns true. Here is a short and concise example:

number_list = range(-5, 5)
less_than_zero = list(filter(lambda x: x < 0, number_list))

reduce is a really useful function for performing some computation on a list and returning the result. It applies a rolling computation to sequential pairs of values in a list.

from functools import reduce
product = reduce((lambda x, y: x * y), [1, 2, 3, 4])

The any function will check if any of the items in a list or iterable are true. Returns a boolean.

y = [True, False, False]
x = any(y)

The all function will check if all the items in a boolean list or tierable are true - returns a boolean

x = [True, True, True]
all(x) == True

Lambda functions

  • defines via func = lambda x: expression e.g. func = lambda x: x+1. Useful for short functions and functions that are passed as arguments to other functions like map, filter

Variable arguments

  • we can define functions that take a variable number of arguments, def function(*args): this turns a set of arguments like function(1,2,3,4,5) into a list within the function.
  • *args and **kwargs allow you to pass multiple arguments or keyword arguments to a function. The * is an unpacking operator that produces a tuple of positional arguments. The ** operator is similar but produces keyword arguments. That is, it produces a dictionary.
def func(*args):
   return args[0], args[3]

func(3,5,1,5,2)
#yields 3, 5

Comprehensions are ways of constructing generators or collections in a single one line.

  • lists [i for i in range(5)]
  • sets {i for i in range(5)}
  • dicts {i:j for i, j in enumerate('hello')}
  • generators (i for i in range(5))

Iterators & generators

A generator is a function that allows you to declare a function that acts like an iterator (which can be used in a for loop). An iterable object in python is built with the __next__ and __iter__ methods but a shortcut to writing iterable functions is via the yieldkeyword. When used, the function continues from when it called yield. Therefore a generator is a special type of iterator.

One can create generators using a loop and the yield keyword. The yield keyword is used in the same way as the return keyword but will instead return a generator

def generate(iterable):
    for value in iterable:
        yield value

They are particularly valuable when performing time or memory intensive computations.

  • the yield from keyword can be used to chain together generators

  • generator expressions : They function more-or-less like list comprehensions or map but avoid the overhead of generating the entire list at once. Instead, they return a generator object which can be iterated over bit-by-bit:

iterator = (s.upper() for s in oldlist)

Advanced iteration

  • use iter on a collection to turn it into and iterator, one can then use next to get the successive elements of the collection.
  • Useful when used in combination with a function and sentinel. iter(function, sentinel) The iterator will call the function successively until the output equals the sentinel value.
  • enumerate iterates over a collection but also returns an index as a tuple. One can also provide a starting value for the index. enumerate(collection, start=1)

When looping over an iterable and you want both the element and the number it is in the sequence, use enumerate

for i, name in enumerate(name_list):
    print(i, name)

will give you

0, 'alice'
1, 'bob'
2, 'catherine'

enumerate produces a list of tuples

  • zip combines multiple sequences into a single iterator.

This iterator generates a series of tuples containing elements from each iterable.

>>> s1 = {2, 3, 1}
>>> s2 = {'b', 'a', 'c'}
>>> list(zip(s1, s2))
[(1, 'a'), (2, 'c'), (3, 'b')]
  • sorted returns a sorted list, also has a reverse keyword if you need to reverse the result
  • reversed returns a reversed list
  • cycle from itertools is a useful standard library function that infinitely loops over a sequence of values
  • count from itertools provides a counter, which iterates by a step size every iteration
  • accumulate from itertools provides an accumulator, which aggregates successive values of a sequence. We can provide a function to define the accumulation function. The default is sum, but max is also useful accumulate(sequence, max)
  • chain from itertools will chain two sequences together. list(chain([1,2,3], "ABC")) yields [1,2,3,"A","B","C"]
  • dropwhile and takewhile from itertools are like filter. They will provide values until a trigger value is reached. Both require a predicate to check the values in the sequence.
  • groupby from itertools calculates the keys for each element present in iterable. It returns key and iterable of grouped items. This function takes two arguments: (1) the data to group and (2) the function to group it with.

Loops & control Flow

  • Standard conditionals control the logical branching of a program, these are the standard if, elif, else
if condition1:
    code
elif condition2:
    code2
else:
    code3
  • Loop with for, while
for i in iterator:
    code
while condition:
    code
  • Control the behaviour of loops with break, continue, pass
for number in range(10):
    if number == 5:
        pass    # pass here

By using the pass statement in this program, we notice that the program runs exactly as it would if there were no conditional statement in the program. The pass statement tells the program to disregard that condition and continue to run the program as usual.

for number in range(10):
    if number == 5:
        continue    # continue here

The continue statement gives you the option to skip over the part of a loop where an external condition is triggered, but to go on to complete the rest of the loop. That is, the current iteration of the loop will be disrupted, but the program will return to the top of the loop.

for number in range(10):
    if number == 5:
        break    # break here

In Python, the break statement provides you with the opportunity to exit out of a loop when an external condition is triggered. You’ll put the break statement within the block of code under your loop statement, usually after a conditional if statement.

  • Exception handling with try, except, raise

try, except and raise are used for exception handling. The program will begin by trying the code in the try block, but if an error is raised, it will run the code in the except block.

try:
  print(x)
except NameError:
  print("Variable x is not defined")
except:
  print("Something else went wrong")

Multiple except statements can be used with specific errors like NameError, ValueError, TypeError,ZeroDivisionError.

The raise keyword will force a particular error to occur. Usually this is used to produce a specific error to inform the user

Classes & objects

  • ‘classes’ act as factories for generating objects (often called instances) and define unique types.
  • Classes may inherit from other classes (their parents), inheriting both data (fields) and behaviour (methods)
  • If B inherits from A, then an instance of B can be passed to something expecting A (subtyping)
  • An object should hide its data (encapsulation), which can only be operated on with methods.

Object-oriented design is then about identifying the classes (the ‘nouns’) and the methods (the ‘verbs’) and then establishing relationships between them, is-a and has-a.

Favour class composition over inheritance. Create more abstract classes by building them form less-abstract classes with has-a relationships.

Pythonic getters and setters with property decorator. properties should only be used when no calculation is performed i.e just simple getting of info. Use full method when some work is being done.

class House:

    def __init__(self, price):
        self._price = price

    @property
    def price(self):
        return self._price

    @price.setter
    def price(self, new_price):
        if new_price > 0 and isinstance(new_price, float):
            self._price = new_price
        else:
            print("Please enter a valid price")

    @price.deleter
    def price(self):
        del self._price

Special class methods allow one to implement particular operators for you custom class.

  • The most useful are __getitem__, __init__, __len__, __call__. These are called to the object using
object[i]
object = class(init_args)
len(object)
object(call_args)
  • custom iterator classes can be created by implementing __next__ and __iter__ methods. These return tell the functions next(x) and iter(x) what to do.

Advanced class methods

  • usually used to assign human-readable names to constant values in program. They have name and value properties. They are from the enum package of the standard library and created like
from enum import Enum
class Fruit(Enum):
    APPLE = 1
    BANANA = 2
  • Fruit.APPLE.name gives APPLE and Fruit.APPLE.value gives 1
  • String representations of classes can be defined by the __str__ and __repr__ methods. They tell the class what to output when str and repr functions are called on the object. the repr version is used for more detailed output for debugging, and str method is for short, human readable description.
  • We can add numeric-like functionality to classes by overriding the following methods: __add__, __sub__, __mul__, __div__, __floordiv__, __pow__, __and__ __or__. These allow the use of binary mathematical operators (like +, -,**) on your object. you can also use the in-place versions of these operations by overriding __iadd__ (for +=) etc.
  • We can do the same with comparison operators: __gt__, __lt__, __ge__, __le__, __eq__, __ne__ for operations like >, >=, == etc. These are useful as they allow the object to be sorted in collections.
  • __slots__ attribute in classes can be used to optimize classes. They allow you to explicitly state which instance attributes you expect your object instances to have, with the expected results:
    1. faster attribute access.
    2. space savings in memory.
class Base:
    __slots__ = 'foo', 'bar'

Abstract base classes

These are a way of defining templates for additional subclasses. We can enforce what methods are required when subclassing by using the Python abc module.

# Implementing Different Methods for Classes
from abc import ABC, abstractmethod

#This is the template class
class Employee(ABC):
    @abstractmethod
    def arrive_at_work(self):
        pass

#These subclasses must implement the arrive_at_work method to avoid errors
class Manager(Employee):

        print("Arriving at datagy.io headquarters!")

class Supervisor(Employee):
    def arrive_at_work(self):
        print("Reporting for duty at datagy.io!")

katie = Supervisor()

Speeding up python

Python is a dynamically-typed scripting language and so is generally very slow and unsuited to computationally intensive tasks,. There are however methods of extending python for more intensive operations. One should try each of these in order:

  1. Check you’re using a optimal algorithm

  2. Try using numpy/scipy

  3. Try using numba, particularly if you have a calculation that cannot be written in terms of numpy/scipy. This also allows for parallelization.

  4. Try using GPU acceleration using pytorch or cupy.

  5. Convert the demanding part of the program into cython and convert to C. This C extension will be much faster than pure python.

  • numba

Numba is an open source JIT compiler that translates a subset of Python and NumPy code into fast machine code. Code can be optimized using a simple decorator.

@numba.jit
def f(x, y):
    return x + y

use with nopython=True for a function where all types can be inferred - much faster code. Use parallel=True for automatic parallelisation.

Functional programming in python

Functional programming is a declarative programming paradigm that treats computation as the evaluation of mathematical functions. It emphasises immutability, first-class functions, and the avoidance of side-effects.

In functional programming, functions are treated as first-class citizens, which means that they can be passed as arguments to other functions, returned as values from functions, and assigned to variables. This enables a style of programming in which functions are composed in a way that is similar to mathematical functions.

The key features of functional programming are

  • Pure functions
    • functions should never change the data in-place
    • functions should have no side effects
    • functions should have no access to external variables
  • Higher-order functions - can take functions as arguments or return them as results
  • Comprehensions
  • Lambda (anonymous) functions
  • Recursion
  • Immutable objects - a function should never change the data in-place
#an example of higher-order functions
def apply_twice(func, arg):
  return func(func(arg))

def add_five(x):
  return x + 5

print(apply_twice(add_five, 10))  # prints 20
#an example of function composition
from functools import reduce

def multiply_by_two(x):
  return x * 2

def add_three(x):
  return x + 3

def compose(f, g):
  return lambda x: f(g(x))

f = compose(multiply_by_two, add_three)
result = reduce(f, [1, 2, 3, 4], 0)
print(result)  # prints 20
#an example of immutability
def remove_duplicates(items):
  seen = set()
  for item in items:
    if item not in seen:
      seen.add(item)
      yield item

items = [1, 2, 3, 3, 4, 4, 4, 5]
result = list(remove_duplicates(items))
print(result)  # prints [1, 2, 3, 4, 5]

Key tools for functional python are, map, reduce , filter

Further functional programming tools are found in the functools and itertools modules.

The itertools module contains valuable functions such as count, cycle, repeat, product, permutations, combinations, accumulate, starmap.

The functools module is for higher-order functions. It includes lots of useful things for composing pure functions, such as reduce and partial.

The key sense of work in the functional paradigm is compositions of pure functions acting on iterables. A very valuable pattern is the map-reduce pattern. The map-reduce pattern is an abstract representation of many types of computations that manipulate lists or collections of objects. The map stage takes the input collection and maps it to an intermediate representation. The reduce step takes this intermediate representation and computes a single output from it.
